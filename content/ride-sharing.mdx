### Routing concept: turn roads into a graph

Imagine intersections `A`, `B`, and `C`. Each intersection becomes a **node**. A road from `A` to `B` becomes an **edge**. The number of travel minutes becomes the edge's **weight**—the cost of using that road.

A straight line on a screen is not a route. A river, one-way street, or missing bridge can make a visually close driver slow or unreachable. This is why matching must compare road-route minutes, not coordinate distance.

RoadGraph stores outgoing edges as an adjacency list: for each node, keep the roads that may be taken from it. A two-way street is two directed edges. This representation uses `O(V + E)` space for `V` locations and `E` road segments.

### Routing and matching are not the same algorithm

Routing receives two locations and returns a path. Matching receives many drivers, filters business state such as AVAILABLE, asks routing about each candidate, and selects one result.

If we mix them, Dijkstra starts checking driver status and Driver begins knowing graph edges. Both classes become harder to test. The design therefore keeps this call direction:

```text
DriverMatchingStrategy
  └─ for each AVAILABLE Driver
       └─ RoutingStrategy.route(driver.location, pickup)
```

The simple matcher runs Dijkstra once per available driver. With `D` drivers, its cost is `O(D × (V + E) log V)`. That is honest and clear for an interview-sized graph. A production system would first use a geographic index or run a reverse/multi-source search to reduce candidates.

### Why breadth-first search is not enough

Breadth-first search, or BFS, minimizes the number of edges. It is correct when every road has equal cost. Here one road may take 1 minute and another 8 minutes.

From `C` to `D`, BFS sees the direct one-edge road `C → D` and returns 8 minutes. But `C → B → D` has two edges and costs only `1 + 5 = 6` minutes. Fewer roads does not mean less travel time.

### Dijkstra's algorithm in plain English

Dijkstra works when every edge weight is non-negative. It grows the cheapest known region outward from the start.

- A **distance estimate** is the best travel time found so far for a node.
- The **frontier** contains discovered nodes whose outgoing roads may still improve other estimates.
- A **priority queue** returns the frontier node with the smallest estimate first.
- A **settled** node has been removed with its cheapest final distance.
- **Relaxing an edge** means asking whether travelling through the current node gives its neighbour a cheaper estimate.
- A **predecessor** records which previous node created an improved estimate, allowing the final path to be rebuilt backward.

Trace `A` to pickup `D` on our graph:

1. Start with `A = 0`; every other distance is infinity, written `∞`.
2. Settle `A`. Roads discover `C = 2` and `B = 4`.
3. Settle `C = 2`. `C → B` improves `B` from 4 to 3. It also discovers `D = 10` and `E = 12`.
4. Settle `B = 3`. `B → D` improves `D` from 10 to 8.
5. Settle `D = 8`. Stop and follow predecessors backward: `D ← B ← C ← A`.
6. Reverse that chain to return `A → C → B → D`, 8 minutes.

The priority queue may hold an older entry such as `B = 4` after `B = 3` is found. The implementation skips stale entries rather than trying to edit the queue in place.

Dijkstra takes `O((V + E) log V)` time with adjacency lists and a binary priority queue, and `O(V + E)` space including the graph, estimates, predecessors, settled set, and queue.

### Dijkstra's assumptions and alternatives

Negative road weights would break the “settled means final” promise, but negative travel time has no physical meaning here. Static positive minutes therefore fit Dijkstra well.

BFS is simpler for equal weights. A* can explore less of a large map by adding a **heuristic**, an estimate of remaining cost such as straight-line time. That heuristic must never overestimate if we want the normal shortest-path guarantee. Coordinates and a safe heuristic are not part of this first model, so forcing A* would add fields without a current need.

<JavaFile name="RoadGraph.java" purpose="Owns locations and immutable outgoing-road adjacency lists.">
{`import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public final class RoadGraph {
    private final Map<String, Location> locations = new LinkedHashMap<>();
    private final Map<String, List<Road>> outgoing = new LinkedHashMap<>();

    public void addLocation(Location location) {
        if (location == null) {
            throw new IllegalArgumentException("Location is required");
        }
        if (locations.putIfAbsent(location.id(), location) != null) {
            throw new IllegalArgumentException("Duplicate location: " + location.id());
        }
        outgoing.put(location.id(), new ArrayList<>());
    }

    public void addDirectedRoad(String fromId, String toId, int minutes) {
        requireLocation(fromId);
        requireLocation(toId);
        outgoing.get(fromId).add(new Road(fromId, toId, minutes));
        outgoing.get(fromId).sort((left, right) -> left.toId().compareTo(right.toId()));
    }

    public void addTwoWayRoad(String firstId, String secondId, int minutes) {
        addDirectedRoad(firstId, secondId, minutes);
        addDirectedRoad(secondId, firstId, minutes);
    }

    public boolean containsLocation(String locationId) {
        return locations.containsKey(locationId);
    }

    public List<Road> roadsFrom(String locationId) {
        requireLocation(locationId);
        return List.copyOf(outgoing.get(locationId));
    }

    private void requireLocation(String locationId) {
        if (!locations.containsKey(locationId)) {
            throw new IllegalArgumentException("Unknown location: " + locationId);
        }
    }
}`}
</JavaFile>

<JavaFile name="DijkstraRoutingStrategy.java" purpose="Finds the cheapest non-negative weighted route with deterministic priority-queue ordering.">
{`import java.util.ArrayList;
import java.util.Collections;
import java.util.Comparator;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.PriorityQueue;
import java.util.Set;

public final class DijkstraRoutingStrategy implements RoutingStrategy {
    private record QueueEntry(String locationId, int minutes) {}

    @Override
    public Optional<Route> route(
            RoadGraph graph,
            String startId,
            String targetId
    ) {
        if (graph == null || !graph.containsLocation(startId)
                || !graph.containsLocation(targetId)) {
            return Optional.empty();
        }
        if (startId.equals(targetId)) {
            return Optional.of(new Route(List.of(startId), 0));
        }

        Map<String, Integer> distance = new HashMap<>();
        Map<String, String> previous = new HashMap<>();
        Set<String> settled = new HashSet<>();
        PriorityQueue<QueueEntry> frontier = new PriorityQueue<>(
                Comparator.comparingInt(QueueEntry::minutes)
                        .thenComparing(QueueEntry::locationId)
        );
        distance.put(startId, 0);
        frontier.add(new QueueEntry(startId, 0));

        while (!frontier.isEmpty()) {
            QueueEntry current = frontier.remove();
            if (current.minutes() != distance.getOrDefault(
                    current.locationId(), Integer.MAX_VALUE)) {
                continue;
            }
            if (!settled.add(current.locationId())) {
                continue;
            }
            if (current.locationId().equals(targetId)) {
                return Optional.of(new Route(
                        rebuildPath(previous, startId, targetId),
                        current.minutes()
                ));
            }

            for (Road road : graph.roadsFrom(current.locationId())) {
                if (settled.contains(road.toId())) {
                    continue;
                }
                int candidate = Math.addExact(current.minutes(), road.minutes());
                int known = distance.getOrDefault(road.toId(), Integer.MAX_VALUE);
                if (candidate < known) {
                    distance.put(road.toId(), candidate);
                    previous.put(road.toId(), current.locationId());
                    frontier.add(new QueueEntry(road.toId(), candidate));
                }
            }
        }
        return Optional.empty();
    }

    private List<String> rebuildPath(
            Map<String, String> previous,
            String startId,
            String targetId
    ) {
        List<String> reversed = new ArrayList<>();
        String current = targetId;
        reversed.add(current);
        while (!current.equals(startId)) {
            current = previous.get(current);
            if (current == null) {
                throw new IllegalStateException("Predecessor chain is incomplete");
            }
            reversed.add(current);
        }
        Collections.reverse(reversed);
        return List.copyOf(reversed);
    }
}`}
</JavaFile>

<JavaFile name="NearestDriverMatchingStrategy.java" purpose="Chooses the reachable available Driver with the lowest pickup minutes, then ID.">
{`import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Optional;

public final class NearestDriverMatchingStrategy
        implements DriverMatchingStrategy {

    @Override
    public Optional<DriverMatch> match(
            List<Driver> drivers,
            String pickupId,
            RoadGraph graph,
            RoutingStrategy routing
    ) {
        List<DriverMatch> candidates = new ArrayList<>();
        for (Driver driver : drivers) {
            if (driver.status() != DriverStatus.AVAILABLE) {
                continue;
            }
            routing.route(graph, driver.currentLocationId(), pickupId)
                    .ifPresent(route -> candidates.add(new DriverMatch(driver, route)));
        }
        return candidates.stream().min(
                Comparator.comparingInt(
                                (DriverMatch match) -> match.pickupRoute().totalMinutes())
                        .thenComparing(match -> match.driver().id())
        );
    }
}`}

<JavaFile name="RideService.java" purpose="Coordinates validation, trip routing, matching, IDs, ride storage, and lifecycle actions.">
{`import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Optional;

public final class RideService {
    private final Map<String, Rider> ridersById = new LinkedHashMap<>();
    private final List<Driver> drivers;
    private final Map<String, Ride> ridesById = new LinkedHashMap<>();
    private final RoadGraph graph;
    private final RoutingStrategy routing;
    private final DriverMatchingStrategy matching;
    private int nextRideNumber = 1;

    public RideService(
            List<Rider> riders,
            List<Driver> drivers,
            RoadGraph graph,
            RoutingStrategy routing,
            DriverMatchingStrategy matching
    ) {
        if (riders == null || riders.isEmpty()
                || drivers == null || drivers.isEmpty()
                || graph == null || routing == null || matching == null) {
            throw new IllegalArgumentException("Service dependencies are required");
        }
        for (Rider rider : riders) {
            if (ridersById.putIfAbsent(rider.id(), rider) != null) {
                throw new IllegalArgumentException("Duplicate rider: " + rider.id());
            }
        }
        this.drivers = List.copyOf(drivers);
        this.graph = graph;
        this.routing = routing;
        this.matching = matching;
    }

    public MatchResult requestRide(RideRequest request) {
        if (request == null) {
            return MatchResult.rejected(MatchStatus.INVALID_REQUEST);
        }
        if (!ridersById.containsKey(request.riderId())) {
            return MatchResult.rejected(MatchStatus.UNKNOWN_RIDER);
        }
        if (!graph.containsLocation(request.pickupId())
                || !graph.containsLocation(request.destinationId())) {
            return MatchResult.rejected(MatchStatus.UNKNOWN_LOCATION);
        }
        if (request.pickupId().equals(request.destinationId())) {
            return MatchResult.rejected(MatchStatus.INVALID_REQUEST);
        }

        Optional<Route> tripRoute = routing.route(
                graph, request.pickupId(), request.destinationId());
        if (tripRoute.isEmpty()) {
            return MatchResult.rejected(MatchStatus.UNREACHABLE_TRIP);
        }
        Optional<DriverMatch> match = matching.match(
                drivers, request.pickupId(), graph, routing);
        if (match.isEmpty()) {
            return MatchResult.rejected(MatchStatus.NO_DRIVER_AVAILABLE);
        }

        DriverMatch selected = match.get();
        String rideId = "R" + nextRideNumber;
        Ride ride = new Ride(
                rideId,
                request.riderId(),
                selected.driver(),
                request.pickupId(),
                request.destinationId(),
                selected.pickupRoute(),
                tripRoute.get()
        );
        if (!selected.driver().assign()) {
            return MatchResult.rejected(MatchStatus.NO_DRIVER_AVAILABLE);
        }
        nextRideNumber++;
        ridesById.put(ride.id(), ride);
        return MatchResult.accepted(ride);
    }

    public RideActionStatus startRide(String rideId) {
        Ride ride = ridesById.get(rideId);
        if (ride == null) {
            return RideActionStatus.RIDE_NOT_FOUND;
        }
        return ride.start()
                ? RideActionStatus.STARTED
                : RideActionStatus.INVALID_STATE;
    }

    public RideActionStatus completeRide(String rideId) {
        Ride ride = ridesById.get(rideId);
        if (ride == null) {
            return RideActionStatus.RIDE_NOT_FOUND;
        }
        if (ride.status() != RideStatus.IN_PROGRESS) {
            return RideActionStatus.INVALID_STATE;
        }
        if (!ride.complete()) {
            return RideActionStatus.INVALID_STATE;
        }
        if (!ride.driver().completeAt(ride.destinationId())) {
            throw new IllegalStateException("Ride and driver state disagree");
        }
        return RideActionStatus.COMPLETED;
    }

    public Optional<Ride> ride(String rideId) {
        return Optional.ofNullable(ridesById.get(rideId));
    }

    public List<Driver> drivers() {
        return drivers;
    }
}`}

<h2 id="extensions">5. Extensions (~5 minutes)</h2>

### “Now include live traffic”

The changed requirement alters edge weights while rides are being requested. RoadGraph currently owns static minutes. Introduce a traffic-aware weight provider or immutable graph snapshot used by one routing call. RoutingStrategy still owns path finding; do not let DriverMatchingStrategy read traffic feeds directly.

### “Use A* on a large map”

The affected rule is route search. Add coordinates to Location, define a safe travel-time heuristic, and implement `AStarRoutingStrategy` behind the existing interface. Keep Dijkstra as a reference and test that the heuristic never overestimates on the chosen road model.

### “Find drivers efficiently across a city”

The naive matcher runs a route for every available driver. Add a geographic index to find a bounded candidate set, then run exact road routing only for those drivers. The index narrows candidates; it does not replace final routing correctness.

### “Allow two riders to request at the same time”

The current sequential assumption prevents both requests from seeing one driver as AVAILABLE. In one Java process, protect candidate selection plus `assign` as one critical operation. Across servers, use a transactional or compare-and-set reservation in shared storage. A local lock alone cannot coordinate separate processes.

### “Let a driver accept or reject”

Ride currently enters MATCHED immediately. Add OFFERED and an offer timeout. The driver's temporary reservation belongs beside the offer state, and a rejection releases the driver before the next matching attempt. This is when a richer State design may become useful.

### “Add pricing and payment”

Fare calculation depends on distance, time, vehicle, and pricing policy; payment is a separate external workflow. Add a PricingStrategy only after its inputs and variations are confirmed. Keep payment failure from corrupting ride routing or driver availability.

### A strong spoken summary

> “I separated matching from routing. RoadGraph owns directed weighted edges. DijkstraRoutingStrategy returns the cheapest path using distance estimates, predecessors, a settled set, and a priority queue. NearestDriverMatchingStrategy calls routing for AVAILABLE drivers and compares pickup minutes, then ID. RideService validates the trip and match before creating a Ride or making a Driver busy. The first version uses static graph minutes and sequential in-memory calls; live traffic, A*, geographic indexing, and concurrent driver reservation are extensions.”
