<h2 id="requirements">1. Requirements (~5 minutes)</h2>

The interviewer begins with one sentence:

> “Design a movie-ticket booking system.”

Do not start drawing `Movie`, `Theatre`, and `Payment` classes. The sentence does not yet tell us what “booking” means. Does selecting a seat immediately buy it? Can a group reserve several seats together? What happens if payment takes two minutes? Most importantly, what happens when two users press the same seat at almost the same time?

Turn the story into actions and rules first. The classes will come from those answers.

Follow the arrows. The **moviegoer** selects A7 and calls **BookingService**. The service finds the correct **Show** and asks it to hold the seat. Show acquires its one lock, checks the relevant **ShowSeat**, and changes AVAILABLE to HELD only if the whole request is valid. A successful change creates a **SeatHold**; otherwise the caller receives a rejection. Later, confirmation follows the hold back into the same Show, changes HELD to BOOKED, and creates a **Booking**.

The key ownership decision is visible in the middle: `BookingService` finds and records, `Show` protects the all-or-nothing operation, and `ShowSeat` owns one seat's valid state. No object reaches across those boundaries to set raw fields.

### Understand the seat state machine

A **state machine** is simply a list of allowed states and allowed moves between them. Here there are only three:

```text
AVAILABLE --successful hold--> HELD --confirmation--> BOOKED
                              |
                              +--expiry--> AVAILABLE
```

There is no direct AVAILABLE → BOOKED move because the confirmed requirements include a hold. There is no BOOKED → AVAILABLE move because cancellation is outside scope. Writing these omissions is useful: it stops an interviewer from wondering whether we forgot them.

### Concurrency: why a normal availability check is not enough

Imagine User A and User B both request A7. This unsafe code looks reasonable:

```java
if (seat.isAvailable()) {
    seat.placeHold(...);
    return HELD;
}
```

The problem is that the `if` check and the state change are separate actions. The operating system may pause one thread between them.

<ScenarioTrace steps={[
  "User A checks A7. The answer is AVAILABLE.",
  "Before A changes anything, User B checks A7. B also sees AVAILABLE.",
  "A changes A7 to HELD and returns success.",
  "B continues using its old answer, changes A7, and also returns success.",
  "Two users were promised one seat."
]} />

This ordering is called an **interleaving**: the steps of two callers are mixed. The bug is a **race condition** because the result depends on which thread happens to run at each moment.

The three steps below form the **critical section**—the part that only one thread may execute at a time:

```text
check every requested seat → change every seat to HELD → record success
```

An operation is **atomic** when other threads observe it as one unit: they see either the state before it or the state after it, never a half-completed group.

### Our choice: one lock per Show

Every `Show` owns one `ReentrantLock`. A caller acquires it before releasing expired holds, validating the entire group, and changing the group. The caller releases it in a `finally` block, so an unexpected exception cannot leave the show permanently locked.

This is a **coarse lock** because it covers every seat in one show. It is a good interview choice:

- The correctness argument is short: only one thread can change a show's seat map at a time.
- A request for A5 and A6 needs only one lock, so there is no partial group booking.
- Different shows have different locks, so the 7:00 PM and 10:00 PM shows can still process work together.
- The trade-off is lower parallel work: a user holding A1 briefly makes a user holding F20 wait, even though the seats do not overlap.

A **fine lock** per seat would let unrelated seats proceed together. But a group request would need several locks. Every caller would have to acquire them in the same sorted order; otherwise one thread could hold A5 while waiting for A6 and another could hold A6 while waiting for A5. That cycle is a **deadlock**: both wait forever. The added complexity is not justified for this in-memory interview scope.

<Insight title="A Java lock has a boundary" tone="warning">
  This lock protects threads that share the same `Show` object inside one Java process. If two application servers each have their own memory, each also has its own lock. Both could still sell A7. A production design needs a shared authority such as a database transaction, a uniqueness constraint, or a distributed reservation service.
</Insight>

### Why holds need an injected Clock

Code that calls `Instant.now()` everywhere is difficult to test: a five-minute expiry test would either wait or depend on timing luck. `BookingService` receives a Java `Clock`. Production can use the system clock; the demo uses `MutableClock` and advances time immediately. The business rule stays real while the test stays fast and repeatable.

### Complexity and limits

For `k` requested seats, checking and updating the group costs `O(k)`. This lesson scans the seats in one show to release expired holds, so an operation also costs `O(S)` for `S` seats. State uses `O(S + H + B)` space for show seats, accepted holds, and bookings. A larger service could maintain an expiry queue, but that would add bookkeeping that this interview version does not need.

### Decide whether patterns help

<PatternDecision name="State pattern" useIt={false}>
  We do have states, but only three simple transitions and very little state-specific behavior. An enum plus guarded methods in `ShowSeat` is easier to follow. Separate AVAILABLE, HELD, and BOOKED classes would add indirection without solving a current problem.
</PatternDecision>

<PatternDecision name="Strategy for pricing or payment" useIt={false}>
  The core design has no price calculation or payment provider. There is no changing rule to isolate yet. If Extensions add several pricing policies or gateways, that requirement would create a Strategy interface at that time.
</PatternDecision>

<PatternDecision name="Singleton BookingService" useIt={false}>
  A global instance would make tests share state and would not make several servers consistent. Normal construction and dependency injection make the clock and sample shows explicit.
</PatternDecision>

### Compare the important production alternatives

<ConceptDropdown title="Optimistic version check" summary="Allow callers to read together, but accept a write only if the seat version has not changed.">
  A seat row can store a version number. A caller reads A7 at version 12 and attempts an update with “only if version is still 12.” One caller changes it to 13; the other update affects zero rows and must retry or reject. This permits more parallel reads, but it needs a shared storage system that can perform the conditional write atomically.
</ConceptDropdown>

<ConceptDropdown title="Database transaction and constraint" summary="Let one shared database make the final ownership decision across application servers.">
  A transaction can lock the requested seat rows, verify them, insert the hold, and update the states before committing. A unique constraint can prevent two active ownership records for the same show and seat. This is the usual direction when the system moves beyond one process, but database design is outside this LLD implementation.
</ConceptDropdown>

<ConceptDropdown title="Temporary hold service" summary="Store holds in shared storage and expire them reliably when payment may run on another server.">
  Production systems often keep a shared hold record with an expiry and a background cleanup process. The final booking operation verifies the live hold inside a transaction. Our `SeatHold` models the same idea locally, which makes the later upgrade understandable rather than magical.
</ConceptDropdown>

<ConceptDropdown title="ReentrantLock" summary="The one primitive that protects a show's check-and-change section." defaultOpen={true}>
  `lock.lock()` waits until the current thread owns the show lock. While it owns the lock, another thread calling the protected methods on that Show waits. `unlock()` is placed in `finally`, which guarantees release even if the protected code throws. We never acquire a second lock while holding this one, so this design cannot form a lock cycle.
</ConceptDropdown>

<ConceptDropdown title="ConcurrentHashMap" summary="Thread-safe service indexes, not the seat-booking guarantee.">
  Competing calls may add or remove different hold and booking records. `ConcurrentHashMap` keeps those map operations safe. It does **not** make “check several seats, then change several seats” atomic; the Show lock provides that larger guarantee.
</ConceptDropdown>

<ConceptDropdown title="AtomicInteger" summary="Generate unique in-process IDs when several threads call the service.">
  `getAndIncrement()` returns one number and advances it as a single atomic action. Two threads therefore cannot receive the same hold sequence number. Like the lock, this uniqueness exists only inside this service process.
</ConceptDropdown>

<ConceptDropdown title="CountDownLatch" summary="Start both demo tasks together without relying on sleep or timing luck.">
  Each task signals that it is ready and waits at the start latch. The demo releases both after both are ready, then counts the successful results. We do not assert which user wins because thread scheduling is intentionally unknown; we assert the correctness property that exactly one wins.
</ConceptDropdown>

import java.util.List;
import java.util.Map;

public final class Screen {
    private final String id;

    public Screen(String id, List<Seat> seats) {

        return id;
    }

    public List<Seat> seats() {
        return List.copyOf(seatsById.values());

}`}

<JavaFile name="ShowSeat.java" purpose="Owns one seat's state and legal transitions for one show.">
{`import java.time.Instant;

public final class ShowSeat {
    private final Seat seat;
    private SeatState state = SeatState.AVAILABLE;
    private String holdId;
    private String heldBy;
    private Instant expiresAt;

    public ShowSeat(Seat seat) {
        if (seat == null) {
            throw new IllegalArgumentException("Seat is required");
        }
        this.seat = seat;
    }

    public String id() {
        return seat.id();
    }

    public SeatState state() {
        return state;
    }

    public boolean isAvailable() {
        return state == SeatState.AVAILABLE;
    }

    public void placeHold(String holdId, String userId, Instant expiresAt) {
        if (!isAvailable()) {
            throw new IllegalStateException("Seat is not available: " + id());
        }
        this.state = SeatState.HELD;
        this.holdId = holdId;
        this.heldBy = userId;
        this.expiresAt = expiresAt;
    }

    public boolean isHeldBy(String expectedHoldId, String userId) {
        return state == SeatState.HELD
                && holdId.equals(expectedHoldId)
                && heldBy.equals(userId);
    }

    public boolean confirmHold(String expectedHoldId, String userId) {
        if (!isHeldBy(expectedHoldId, userId)) {
            return false;
        }
        state = SeatState.BOOKED;
        clearHoldDetails();
        return true;
    }

    public boolean releaseIfExpired(Instant now) {
        if (state == SeatState.HELD && !now.isBefore(expiresAt)) {
            state = SeatState.AVAILABLE;
            clearHoldDetails();
            return true;
        }
        return false;
    }

    private void clearHoldDetails() {
        holdId = null;
        heldBy = null;
        expiresAt = null;
    }
}`}
</JavaFile>

<JavaFile name="HoldResult.java" purpose="Carries a status and an optional accepted hold.">
{`import java.util.Optional;

public record HoldResult(HoldStatus status, Optional<SeatHold> hold) {
    public HoldResult {
        if (status == null || hold == null) {
            throw new IllegalArgumentException("Result fields are required");
        }
    }

    public static HoldResult accepted(SeatHold hold) {
        return new HoldResult(HoldStatus.HELD, Optional.of(hold));
    }

<JavaFile name="Show.java" purpose="Owns per-show seat state, the lock, and atomic group transitions.">
{`import java.time.Instant;
import java.util.LinkedHashMap;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.concurrent.locks.ReentrantLock;

public final class Show {
    private final String id;
    private final Movie movie;
    private final Screen screen;
    private final Instant startsAt;
    private final Map<String, ShowSeat> seatsById = new LinkedHashMap<>();
    private final ReentrantLock lock = new ReentrantLock();

    public Show(String id, Movie movie, Screen screen, Instant startsAt) {
        if (id == null || id.isBlank() || movie == null
                || screen == null || startsAt == null) {
            throw new IllegalArgumentException("Complete show details are required");
        }
        this.id = id;
        this.movie = movie;
        this.screen = screen;
        this.startsAt = startsAt;
        for (Seat seat : screen.seats()) {
            seatsById.put(seat.id(), new ShowSeat(seat));
        }
    }

    public String id() {
        return id;
    }

    public Movie movie() {
        return movie;
    }

    public Screen screen() {
        return screen;
    }

    public Instant startsAt() {
        return startsAt;
    }

    public HoldStatus tryHold(
            String holdId,
            String userId,
            List<String> requestedSeatIds,
            Instant now,
            Instant expiresAt
    ) {
        if (holdId == null || holdId.isBlank()
                || userId == null || userId.isBlank()
                || requestedSeatIds == null || requestedSeatIds.isEmpty()
                || now == null || expiresAt == null
                || !expiresAt.isAfter(now)) {
            return HoldStatus.INVALID_REQUEST;
        }

        Set<String> uniqueSeatIds = new LinkedHashSet<>(requestedSeatIds);
        if (uniqueSeatIds.size() != requestedSeatIds.size()
                || uniqueSeatIds.stream().anyMatch(id -> id == null || id.isBlank())) {
            return HoldStatus.INVALID_REQUEST;
        }

        lock.lock();
        try {
            releaseExpired(now);

            // First pass: validate the complete group without changing it.
            for (String seatId : uniqueSeatIds) {
                ShowSeat seat = seatsById.get(seatId);
                if (seat == null) {
                    return HoldStatus.SEAT_NOT_FOUND;
                }
                if (!seat.isAvailable()) {
                    return HoldStatus.SEAT_UNAVAILABLE;
                }
            }

            // Second pass: all checks passed, so change the whole group.
            for (String seatId : uniqueSeatIds) {
                seatsById.get(seatId).placeHold(holdId, userId, expiresAt);
            }
            return HoldStatus.HELD;
        } finally {
            lock.unlock();
        }
    }

    public ConfirmationStatus confirmHold(SeatHold hold, Instant now) {
        lock.lock();
        try {
            if (!now.isBefore(hold.expiresAt())) {
                releaseExpired(now);
                return ConfirmationStatus.HOLD_EXPIRED;
            }

            for (String seatId : hold.seatIds()) {
                ShowSeat seat = seatsById.get(seatId);
                if (seat == null || !seat.isHeldBy(hold.id(), hold.userId())) {
                    return ConfirmationStatus.HOLD_NOT_FOUND;
                }
            }
            for (String seatId : hold.seatIds()) {
                seatsById.get(seatId).confirmHold(hold.id(), hold.userId());
            }
            return ConfirmationStatus.BOOKED;
        } finally {
            lock.unlock();
        }
    }

    public Map<String, SeatState> seatStates(Instant now) {
        lock.lock();
        try {
            releaseExpired(now);
            Map<String, SeatState> snapshot = new LinkedHashMap<>();
            for (ShowSeat seat : seatsById.values()) {
                snapshot.put(seat.id(), seat.state());
            }
            return Map.copyOf(snapshot);
        } finally {
            lock.unlock();
        }
    }

    private void releaseExpired(Instant now) {
        for (ShowSeat seat : seatsById.values()) {
            seat.releaseIfExpired(now);
        }
    }
}`}

    private final Duration holdDuration;

                || holdDuration.isZero()) {
            throw new IllegalArgumentException("Shows, clock, and hold duration are required");
        }

        this.holdDuration = holdDuration;
        this.showsById = new LinkedHashMap<>();

            }
        }

            String showId,
            String userId,
            List<String> seatIds

        if (show == null) {
            return HoldResult.rejected(HoldStatus.SHOW_NOT_FOUND);
        }

        Instant now = clock.instant();
        String holdId = "H" + holdSequence.getAndIncrement();
        Instant expiresAt = now.plus(holdDuration);
        HoldStatus status = show.tryHold(
                holdId,
                userId,
                seatIds,
                now,
                expiresAt
        );
        if (status != HoldStatus.HELD) {

                userId,
                seatIds,
                expiresAt
        );

        return HoldResult.accepted(hold);

    public ConfirmationResult confirmHold(String holdId, String userId) {
        SeatHold hold = holdsById.get(holdId);
        if (hold == null) {
            return ConfirmationResult.rejected(
                    ConfirmationStatus.HOLD_NOT_FOUND
            );
        }
        if (!hold.userId().equals(userId)) {
            return ConfirmationResult.rejected(
                    ConfirmationStatus.NOT_HOLD_OWNER
            );
        }

        Instant now = clock.instant();
        Show show = showsById.get(hold.showId());
        ConfirmationStatus status = show.confirmHold(hold, now);
        if (status != ConfirmationStatus.BOOKED) {
            if (status == ConfirmationStatus.HOLD_EXPIRED) {
                holdsById.remove(holdId, hold);
            }
            return ConfirmationResult.rejected(status);
        }

        Booking booking = new Booking(
                "B" + bookingSequence.getAndIncrement(),
                hold.showId(),
                hold.userId(),
                hold.seatIds(),
                now
        );
        bookingsById.put(booking.id(), booking);
        holdsById.remove(holdId, hold);
        return ConfirmationResult.accepted(booking);

    public Map<String, SeatState> seatStates(String showId) {
        Show show = showsById.get(showId);
        if (show == null) {
            return Map.of();
        }
        return show.seatStates(clock.instant());
    }

        return Optional.ofNullable(bookingsById.get(bookingId));
    }

### What to notice in the code

`Show.tryHold` intentionally makes two passes while holding one lock. The first pass only checks; the second pass changes. Returning during the first pass cannot leave A1 held when A2 fails. `ShowSeat.placeHold` still checks its own state, which protects its local rule against programmer misuse.

`Show.confirmHold` checks expiry before confirming. The same Show lock prevents a confirmation and a competing hold from changing the seats at the same moment. `BookingService` creates a `Booking` only after Show reports `BOOKED`, so the receipt never claims success before the state change succeeds.

The demo's concurrent winner is intentionally unknown, but its output property is deterministic: `concurrent success count` must always be `1` and A7 must finish as `HELD`.

<h2 id="extensions">5. Extensions (~5 minutes)</h2>

In an interview, extend the design by naming the new rule first. Then show the smallest boundary it changes.

### Add real payment without holding a lock during a network call

Never keep the Show lock while calling a payment provider. Network calls can take seconds or fail. The hold already provides the safe boundary:

1. Create a five-minute hold under the Show lock.
2. Release the lock.
3. Call the payment provider using the hold ID as the order reference.
4. If payment succeeds before expiry, confirm the hold under the lock.
5. If it fails, release the hold or let it expire.

If several providers are supported, `PaymentStrategy` becomes useful because the requirement now contains a replaceable behavior. It was not useful in the core design.

### Move from one process to several servers

Replace the in-memory authority with shared storage. A database transaction should verify the live hold and create the booking together. Use conditional updates or constraints so only one server can claim a show-seat record. Keep the domain objects and state names, but do not pretend `ReentrantLock` crosses the network.

### Make expiry efficient

The simple implementation scans a show's seats when an operation arrives. A busy service could keep holds ordered by `expiresAt` in a priority queue or a shared expiry index. A background worker releases the earliest expired records first. The difficult requirement is not the timer—it is making cleanup and confirmation agree atomically in shared storage.

### Add pricing, seat categories, and refunds

Add `SeatType` and a pricing rule only when prices enter the requirements. If pricing varies by show, day, or promotion, a `PricingStrategy` can isolate that calculation. Cancellation would add a BOOKED → AVAILABLE transition only after the refund and cancellation rules are clarified; it should not be smuggled into the current state machine.

  First make the workflow precise. Then separate physical seats from per-show state, protect the smallest understandable critical section, and state exactly where that protection stops. That reasoning is more valuable than naming many patterns.
